## Invariants

| # | Invariant |
|---|---|
| I1 | Solvency: pool mUSD + outstanding debt + recorded bad debt ≥ lender funds |
| I2 | `totalCollateral` = sum of positions |
| I3 | `totalDebt` = sum of positions |
| I4 | A glide never leaves health above comfort (+0.001) |
| I5 | No glide when starting health ≥ comfort |
| I6 | Pool mETH balance ≥ `totalCollateral` |
| I7 | **Glide dominates cliff (when no backstop fired):** for mirrored positions on the same price path, once the ghost has been liquidated, the value Soft Landing took to unwind (fees + slippage at the oracle price) ≤ the value the cliff took (its bonus) |

The handler drives random deposits, borrows, repays and withdrawals, ±3%-per-block moves, sustained sell-offs and occasional 15–30% gaps. A keeper pokes and liquidates every block. Counters in the handler confirm that glides, backstops, cliff liquidations and I7 comparisons all actually occur. An earlier version of I7 passed only because it never compared anything.

## What the invariants found

1. **Full-close backstop re-created the cliff (fixed).** The first backstop sold enough to repay 100% of the debt. With two calls (a price rise, then one gap), three positions backstopped in the same block and dumped into the AMM one after another. The last one lost 1,197.8 mUSD, versus 1,190.0 for its cliff ghost. The backstop now sells only what restores comfort at worst-case execution, and closes out only if restoring comfort is impossible. See [mechanism.md](mechanism.md#backstop-health-below-floor).
2. **Back-to-back gaps: backstop cost can equal the cliff bonus (known limit).** Two ~30% gaps in consecutive blocks, with every position backstopping twice, produced a soft loss of 1,190.35 vs a cliff loss of 1,190.00 (0.03% worse). This is why I7 is scoped to "no backstop fired", as the spec defines it. The gliding path, which is the product, dominates. The gap path is roughly even with the cliff.

## Attack scenarios (`test/scenarios/AttackScenarios.t.sol`)

| # | Attack | Before | After |
|---|---|---|---|
| A1 | Dump the AMM ~25% below the oracle, then `poke(victim)` | Naive router (no band, no `minOut`): victim loses **201 mUSD** | `SliceRouter`: sale skipped, victim loses **0** |
| A2 | Stale oracle (10 min, max age 60 s), try to borrow | — | Reverts `StalePrice` |
| A3 | Victim below comfort calls `withdraw` to escape | — | Glide settles first, health check reverts, glide still happens on the next poke |
| A4 | 100 pokes in one block to farm tips | — | One tip paid |
| A5 | Collateral token re-enters `withdraw` from `transferFrom` | — | Reverts `ReentrancyGuardReentrantCall` |
| A6 | Oracle −40% in one update | — | Backstop restores comfort; totals and solvency hold |
| A7 | 10,000 deposits and withdrawals of 1 wei | — | Totals exact; nothing gained or lost |

## Slither findings

| Detector | Where | Status |
|---|---|---|
| `divide-before-multiply` (×7) | `_health`, `sNeeded`, `backstopSlice`, `previewPath`, `SliceRouter.trySell` | **Accepted.** Deliberate WAD rounding, at most a few wei per step. It rounds down, so health reads marginally low (conservative). The TypeScript simulator reproduces the same order exactly (parity vectors) |
| `incorrect-equality` (×4) | `d == 0`, `n == 0` checks | **False positive.** Exact zero checks on integers, not on balances an attacker can nudge |
| `pyth-unchecked-confidence` | `PythOracleAdapter.getPrice` | **False positive.** Confidence is checked in `toWad` (≤ 1% of price); tested in `test_revertsOnWideConfidence` |
| `reentrancy-no-eth`, `reentrancy-benign`, `reentrancy-events` | `_glide`, `_backstop`, `poke`, `pokeMany`, `SliceRouter.trySell` | **Accepted.** Position updates follow the router call because they need its output. Every external entry point of the pool is `nonReentrant` (tested in A5), and the router and AMM are owner-set contracts |
| `uninitialized-local` (×3) | `shortfall`, `repayAmt`, `price` | **False positive.** Zero is the intended default |
| `unused-return` (×2) | `oracle.getPrice()` `updatedAt` | **Accepted.** Staleness is enforced inside each oracle, which reverts |
| `calls-loop` (×4), `costly-loop` (×5) | `pokeMany` | **Accepted.** Bounded at 20 users. A failing oracle reverts the whole batch; the keeper falls back to single pokes |
| `timestamp` (×2) | `MockOracle.getPrice`, `MockToken.faucet` | **Accepted.** Mock contracts; minute-scale timing is fine |

## Known limits

- Owner can change the oracle and router (`Ownable2Step`, events emitted). Roadmap: timelock.
- Backstop under back-to-back gaps is roughly even with the cliff (above).
- No lender withdrawals and no interest in the MVP.
- Keeper outage delays glides. Anyone can poke, and every user action glides, but accrual is capped at 100 blocks per poke.
